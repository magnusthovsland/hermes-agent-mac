# Consent-gated browser analytics

- Reuse existing initializer/capture wrappers and scope changes by environment. QA delivery means the actual QA deploy, not a feature preview. Keep independent products/projects separate. Distinguish pseudonymous browser profiles from authenticated identity. For Wright, authenticated student identity is intentionally unavailable to PostHog: do not propose login-based merging or import Ovio identity to complete this task.
- Prefer the smallest existing SDK/reference-product pattern over a new attribution or identity framework. Measure identity continuity and event attribution independently before proposing architecture: the same distinct ID can survive a new tab while campaign fields disappear. Do not merge profiles to fix missing event properties, infer identity from IP/device similarities, or estimate how often users switch tabs without evidence. Explain any proposed reduction of agreed coverage explicitly rather than silently treating reference-product parity as approval.
- Prefer persisted consent over cached CMP instance state across tabs. Fail closed for missing, malformed or conflicting host/parent-domain cookies. Test grant events arriving before persistence; synchronization must eventually observe a valid grant without granting early.
- Inspect the locked SDK and actual distributed bundle. Opt-out may not empty retry queues; shutdown may flush. Source-private names may be minified away. Never monkeypatch private/minified queues.
- Explain a consent blocker as a short user journey: desired behavior, observed behavior, and practical consequence. Distinguish a value embedded in a locally stored referrer from a value transmitted to PostHog or an ad platform; distinguish previously queued events from newly created ones. State whether evidence is source inspection, an isolated reproduction or observed live behavior, and whether analytics withdrawal or marketing-only withdrawal was tested. Do not imply ordinary checkout is broken or production customer data was exposed from a synthetic probe.
- Verify configuration effects against every storage path, including session-source properties and raw referrers, not just campaign superproperties. A flag that disables one collection path does not establish that an independent SDK subsystem stops persisting it. Treat a failing configuration experiment as an unresolved acceptance test, not a recommended fix; do not trade away stable identity or ignore queued retries to make a storage test pass.
- Establish the attribution contract before choosing storage: field/source, downstream consumer, encoding, consent category, lifetime and conflict rules. Carry forward approved choices rather than repeatedly reopening them; ask only for unresolved decisions, and continue independent approved work. Treat agreement with replacement rules as approval of those rules, not approval of a storage lifetime that was explicitly left unresolved. Prefer built-in SDK/platform mechanisms plus a small adapter; a custom localStorage context is an option to justify, not a default best practice. Preserve opaque values and distinguish browser references from click references; never relabel fbclid as fbc. Define percent/plus decoding using the producer's contract rather than a prototype convention. Do not suppress all cookie click references merely because any UTM or unrelated-platform campaign is present; this can discard valid matching data. Test same-platform conflicts and separate-platform references independently. Re-read approved cookies at relevant actions where suitable; if copies are needed, specify their expiry and withdrawal behavior explicitly because document.cookie does not expose expiry.
- Agree the purpose and consent policy for analytics and marketing fields before implementation; do not present an engineering assumption as a vendor requirement or a legal conclusion. Once agreed, test all collection paths against that policy. In posthog-js, targeting-gating custom cookie helpers does not gate built-in click-ID/Meta collection. Check actual stored initial/current URL and referrer fields as well as nested person payloads: URL masking does not imply referrer masking, and before_send runs after persistence. Reductions from analytics+marketing to analytics-only must also invalidate already queued marketing payloads; preserve permanent cancellation until those retries are discarded.
- Verify cancellation at transport time: retries can bypass capture filters, and polling or events alone cannot protect frozen/background tabs. Before calling a transport hook supported, inspect the exact published public types and documentation; runtime forwarding alone proves behavior, not an API guarantee. Where an AbortSignal mechanism is available, test forwarding/cloning, request-time consent and fallback transports against the distributed SDK. Keep failed candidate mechanisms as unresolved test evidence, not a recommended workflow.
- Do not replace an aborted signal until old retries are provably discarded. SDK retries may re-read current config. Reload-on-reconsent is a possible explicit tradeoff; disclose interrupted unsaved state.
- A necessary same-origin revocation revision can protect a suspended tab across another tab's withdrawal/regrant. Do not confuse it with analytics identity or claim same-origin storage events span sibling origins. Document cross-origin limitations.
- Clear only the selected project's browser storage, including legacy parent-domain cookies; retain necessary denial state. Browser withdrawal does not delete historical server data.

## Event-design preferences and delivery boundaries

- Give Magnus a readable action log: include entity names alongside stable IDs so analysis does not require database access. Capture names at event time; keep package product identity distinct from a selected course occurrence.
- Separate actual page openings (`$pageview`, including SPA navigation) from deliberate actions. A summary-page visit is not a continuation click, and a continuation click is not completed login or payment. Use consistent action names across placements, with properties for location, product type and login method.
- When sanitizing SDK envelopes, preserve Date timestamps and unknown non-plain objects; rewrite only actual attribution query keys, not every string containing `?`. Validate native before-send input/output and serialized transport timestamps, ordinary text and relative hrefs, not just attribution fields. Test first marketing grant separately from withdrawal/regrant, and cross-tab campaign A → untagged → other-tab B → return A while preserving stale-background-tab protection. Broad green field matrices can miss envelope corruption and these lifecycle transitions.
- Test the full event contract, not just event names/counts: require `$pageview` metadata at initial consent and SPA transitions, and verify ID namespaces through real mapper-to-handler paths. In Wright's installed React Router, `useMatches()` exposes `loaderData`; prove the actual installed router shape rather than assuming older `.data` examples. Combine independently modified shared-component branches locally and exercise both suites: narrowly mocked hooks and exact-source regex assertions can fail even when application code merges cleanly.
- Reconcile proposed coverage with the user's actual path and every UI entry point. Instrumenting a package's office selector does not cover office-directory links. Count real mouse/keyboard activation, not mount, defaults, or accordion closing. Describe an ambiguous event by its visible button label, location and effect before proposing a rename; distinguish expanding inline dates from opening a selection page and choosing an occurrence. Treat a proposed rename as unapproved until explicitly accepted.
- Keep event instrumentation, campaign attribution, consent policy and cross-domain handoff as distinct acceptance scopes. Approval of a larger event specification must not hide unfinished attribution work, and proof of one scope does not prove another.

For exact Wright event names, summary payloads and QA reload boundaries, follow `references/wright-event-contract.md`. For campaign replacement, retention review, the field matrix and CookieScript disclosures, use `references/attribution-contract-and-retention.md`. Design specifications are not deployment authorization.

## Evidence

- Use RED/GREEN unit tests and real-SDK browser fixtures with synthetic tokens/intercepted ingestion. Payload profile flags are not proof of real server ingestion or a searchable People profile.
- When recursively sanitizing SDK envelopes, traverse only plain records/arrays and preserve Date timestamps and unknown class instances. Assert actual before_send timestamp identity and serialized transport timestamps, not merely event properties. Rewrite strings only for actual attribution query keys; preserve prose and relative-path form.
- Distinguish a landing never permitted by targeting consent from a previously permitted click cleared on withdrawal. Test persisted analytics-only consent followed by first targeting grant without pre-grant raw marketing persistence, then withdrawal/regrant without replay.
- In cross-tab attribution, test two independently located helper instances sharing storage and two open real browser tabs. Reset document-local handled markers on per-group untagged transitions, while retaining protection against unchanged tagged background tabs; exercise a genuine return to the earlier campaign after another tab replaced it.
- For enriched SPA pageviews, register only committed router context and let the consent controller capture once when both consent and current context are ready. Test startup-before-router and router-before-grant, stale context after navigation, StrictMode, and package-plus-course identity. Verify the installed router's actual match shape (React Router 8 uses `loaderData`, not `data`) with a rendered `useMatches` probe; mocks must not silently preserve obsolete APIs.
- Responsive action fixtures must load the actual emitted CSS, toggle the real mobile menu and preserve root/header lifetime across route screens. An unstyled fixture can expose controls hidden in production, and unmounting persistent root UI can create artificial failures. Never force-click a hidden placement merely to reach an event-count target; report visible coverage by viewport. Keep mocked loaders, hosted controls, submission and intercepted navigation explicit.
- For a user's CSV/session-log review, parse rows and counts programmatically, sort by event timestamp and reconstruct each described flow. If authorized, query the same distinct ID and bounded period directly from PostHog. Separate named actions from autocapture text/href evidence and distinguish missing instrumentation from a genuinely absent user action. Do not infer consent from an export without consent evidence, repeat IP addresses/tokens unnecessarily, or use local unshipped instrumentation to explain deployed events.
- Cover no choice/reject/marketing-only/analytics-only/all, StrictMode/remount, SPA/reload/revisit, partial/full withdrawal, 503/in-flight/retry, rapid regrant and unavailable storage/transport.
- Keep both tabs open for cross-tab tests. Seed stale CMP snapshots and freeze one tab. Remove adapter listeners/polling to verify denial at the request boundary independently of notification delivery. A closed original tab only tests revisit.
- Observe native fetch/XHR/beacon and automation/bot filtering to avoid vacuous passes. Seed host and parent-domain cookies plus another project's cookie for selective cleanup tests.
- Build and compare full normalized typecheck diagnostics with the pinned unmodified baseline. Report existing errors honestly.
- After approved merge/deploy, verify real CMP timing, network cessation, intended project ingestion, searchable profile and event log. Report local versus deployed proof separately.
- Build a live acceptance matrix before parallel tests: assign action handlers, each page type, summary variants, consent cases and responsive navigation explicitly. Label field-by-event assertions separately from independent browser journeys. A narrow green regression for one added parameter must not hide a red overall contract; retain a failing full-suite exit status and summarize failure classes rather than presenting a large assertion count as broad journey coverage. Mobile layout/consent checks do not prove mobile-menu events. Merge evidence programmatically against the matrix and run focused supplementary tests for uncovered cases before reporting completion.
- For safe live continuation tests, intercept the actual login-redirect POST at the network boundary after the real click handler, record its outgoing parameters and allow QA analytics ingestion. Verify the resulting event independently server-side. State that login/order/payment was deliberately blocked; this proves the Wright action and payload, not downstream authentication or conversion.
- When a conditional control is absent, inspect its source render predicate and filters before crawling more pages. After a bounded live search, report a test-data gap rather than an instrumentation failure or a pass. Request the minimum QA data that satisfies the predicate; do not fabricate occurrences, force hidden controls or switch to PROD to complete the count. Re-test opening, closing and reopening with native activation and server ingestion once data exists.
- For live posthog-js automation tests, inspect both user-agent/brands and navigator.webdriver filtering. Use an isolated test browser with normal browser UA and webdriver=false before navigation, without altering deployed SDK configuration; disclose this harness adjustment. Negative consent checks are meaningful only when the same harness proves positive ingestion.
- Force fresh PostHog HogQL reads with refresh='force_blocking' and inspect is_cached when polling live ingestion; repeated identical queries may otherwise keep returning an earlier cached event list. Verify person records independently through the project's persons endpoint.
- For inline course expansion, preserve baseline and each expand/collapse/reopen server read plus visible date counts; expect cumulative action counts 0/1/1/2. If role-based discovery cannot find a visibly rendered control, inspect its DOM and use a visible text-filtered native locator click without force; do not dispatch synthetic events. Reused standalone Playwright harnesses may require `uv run --with playwright` and `channel='chrome'` when their bundled browser revision is unavailable.
- In Playwright network observers, do not synchronously evaluate page JavaScript to obtain document IDs: CMP reloads can destroy the execution context and lose the very request being measured. Log document UUID/time from an init script, filter out child frames (including preview-tool iframes), and correlate requests with the latest main-document marker. Distinguish same-origin assets whose names contain posthog from actual ingestion POSTs.
### Attribution verification sequence

1. Inspect the exact deployed/locked SDK and existing helpers to identify built-in fields before adding parsers. Describe this only as implementation support, not proof that a campaign field works end-to-end.
2. With authorization, use a unique synthetic marker on the actual QA landing URL and real CMP choices. Isolate the browser, allow the intended analytics project and prevent ad/conversion delivery. Preserve proof of the loaded build and distinguish synthetic tests from a real advertising-platform click.
3. Follow actual UI links to untagged product and summary routes, then reload in the same tab. Read ingestion back uncached and require the marker in the structured event property; appearance only inside `$current_url` is insufficient. Retrieve the person independently and distinguish current event attribution from initial person fields such as `$initial_oppref`.
4. Open an untagged no-opener tab and repeat. Shared distinct/session IDs or an intact initial person property do not prove event-level attribution persists across tabs. Report same-tab, new-tab and revisit coverage separately rather than saying a field is generally 'handled'.
5. Test cookie-only input with a clean identity and no URL marker. Verify the cookie is present after consent/reload and during capture, because the CMP may remove an unclassified cookie. If necessary reseed after consent and trigger an existing SPA event. Disclose a synthetic cookie's format and do not generalize its result to a real pixel cookie without verifying the serialization contract. Distinguish absent event keys from null person properties.
6. Test a known-supported campaign field as a positive control and each custom field explicitly; preserve opaque values such as `utm_id` without numeric coercion. An empty column in an export is not evidence of working capture or of a consent category. Verify custom campaign configuration separately for event, initial-person and session-entry properties: extending event campaign fields need not extend the SDK's independent initial/session-source paths. Decode `$set`/`$set_once` at the actual transport envelope level rather than assuming they remain nested in `properties`. Seed same-platform replacement tests in an independent context with a positive old-click control; a preceding campaign/new-tab test may already have cleared the old reference and create a vacuous pass.
7. Compare no-consent, analytics-only, combined-consent and marketing-withdrawal cases independently, including persisted URL/referrer copies and queued requests. Report untested cases instead of extrapolating from a positive URL test.
8. Record per-case result, marker, event/person handle and exact property name without exposing API keys or unrelated visitor data. Verify cross-domain delivery and receiver persistence separately: successful PostHog capture does not prove the identifier reaches checkout or a purchase-conversion adapter.
### CMP reload diagnosis and isolated testing

- For CookieScript reload testing, prefer the documented paid-plan staging workflow over private runtime overrides. Staging saves freeze the live CDN configuration, but OFF+save publishes the current configuration and can promote staging scan reports. Staging does not record consents/statistics and is not for real visitors or permanently divergent configurations. Verify the official GTM template's URL validator: its allowed hosts may reject the documented dev-cdn host even when inject-script permissions allow subdomains; do not invent an alternate staging URL. Check actual account eligibility and installation code before proposing activation.
- Diagnose close-together initial pageviews with per-document UUIDs, navigation type, consent/lifecycle timestamps and decoded native-fetch payloads. A CMP can synchronously emit acceptance (starting analytics) and then reload, producing one legitimate SDK capture in each of two documents. Distinguish per-document idempotence from one logical view across CMP reloads; do not suppress the next pageview in storage or add arbitrary delays without a defined reload contract. Inspect the actual CMP reload call order read-only before proposing changes.
