# Auditing server-side conversion tracking

Use a read-only, commit-pinned snapshot for every repository involved; distinguish source state from deployed behavior and externally configured CMP/analytics destinations.

- Trace the complete order of state writes, entitlement grants, analytics capture, payment capture and receipts. A local COMPLETED status or access activation is not proof of captured funds when it precedes the PSP capture response.
- Inspect actual idempotency code before alleging duplicate purchases. Distinguish conditional database transitions, provider capture keys, receipt locks, event IDs and destination deduplication. Check named SQL parameters against method arguments, and state clearly whether tests were executed.
- Treat client loaders and effects as browser event producers even when their URL flags originate in server-side Auth0 callbacks. Trace identify to the internal database ID, not merely the Auth0 subject. A posthog-js reset inside a .server file does not reset browser persistence.
- Audit each consent state separately: before choice, rejection, individual categories and withdrawal. Memory persistence and process_person_profile=false do not mean that no events are sent. Keep email-marketing/terms consent separate from CMP analytics/advertising consent.
- Follow server fetch headers end to end. credentials:include in server-side fetch does not forward an incoming browser Cookie header. Check both initial consent gates for click-ID storage and renewed consent checks before forwarding existing IDs.
- Distinguish late-consent capture from initial-request capture: a hidden form field may retain a URL click ID until submission, when the server reads the newly accepted consent. Do not claim late consent always loses attribution; test consent alone, later submit, internal navigation, language changes and authenticated redirects separately.
- Inventory active routing before auditing landing components: old source files may no longer be registered. Check raw query preservation in returnTo cookies separately from dedicated click-ID cookies and their consent gates.
- Use isolated function tests when the full app/runtime is unavailable. Execute the actual source with real cookie/parser dependencies and mocked network/Auth0/DOM, label this as function testing rather than browser or PSP verification, and save results plus source hashes. Match the project's declared runtime and locked dependency versions. Assert desired acceptance criteria; a test reproducing a defect is not an acceptance pass.
- Verify staging isolation before synthetic journeys: compare live tag/project fingerprints and payment mode without executing analytics. Shared production tags or unknown receiver filters block external synthetic traffic; use loopback-only fixtures instead and mark staging criteria not tested.
- Verify deployed identity through aliases/deployment metadata or running image digests. Branch heads and successful deployment workflows are evidence of source/attempted deployment, not proof of current production or QA state.
- Execute suspicious SQL bindings on the actual ORM/compiler/database stack before calling them bugs. Named-placeholder spelling mismatches can still bind successfully; report the demonstrated behavior and keep concurrency/recovery as separate criteria.
- Inspect Google Ads conversion_action IDs, types, status, primary flag, value settings and windows via read-only GAQL. An AW tag is not an action; removed browser actions do not establish current browser/server double-counting. Offline upload summaries identify the API client, not necessarily PostHog as the uploader.
- Separate sent payload, per-item acceptance (including partial failures), and attributed reporting. Compare ordinary date metrics with *_by_conversion_date in the account timezone; capture/payment and upload dates are separate. Aggregates cannot reconstruct an order-level proof chain.
- Preserve User purchased access as a possible confirmed-purchase source after fixing its trigger and documenting cutover; do not require a new event name. Keep User activated access as an entitlement event.
- Use a standalone PostgreSQL testdatabase for CI-style integration tests when Docker is absent; preserve production source, restrict runtime egress to loopback, record mock boundaries, and stop the isolated database afterward.
- Trace attribution into durable order storage, not just SDK defaults, cookies, callback query strings or polling memory. For an unexplained field such as oppref, report absence from source and seek observed payloads rather than inventing its meaning.
- Inspect active inline analytics initialization as well as config files: open-page apps may bypass an otherwise configured first-party proxy. A rewrite does not prove client-IP preservation. Label data-center geolocation explanations as hypotheses until actual forwarded headers and ingest behavior are verified.
- Distinguish a Node SDK's in-memory buffer/retry from a durable outbox. Recommend atomic local order-transition+outbox writes, at-least-once delivery with stable IDs, and PSP reconciliation rather than claiming distributed exactly-once delivery.
- Keep secret-bearing configuration and raw customer payloads out of audit output; cite paths/lines and public integration identifiers only.
