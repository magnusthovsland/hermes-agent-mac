# Read-only SMS provider migration audits

- Pin the reviewed repository snapshot to an immutable commit and verify the downloaded archive prefix. Treat the default branch as the review scope, not proof of the production deployment; inspect workflows and runtime-profile injection separately.
- Separate counts: direct HTTP operations, provider-interface send calls, sender-resolution calls, and indirect business callers. Save a machine-readable call inventory; do not count imports, definitions, iterations, or constructor references as send sites.
- Trace the entire callback path: servlet context (including camelCase `contextPath`), dynamic MVC/package prefixes, and controller mappings. Searching only `context-path` misses effective routes. Check the security chain separately; documentation hiding is not authentication.
- Trace provider coupling beyond the client: DTOs, sender rules, provider enum, recipient extensions, external-ID lookup, office/tenant number mapping, frontend-facing response dispatch, migrations and tests. An interface using provider-specific DTOs is not a neutral adapter.
- Distinguish office-level routing from tenant-level routing. Short-code plus subnumber cannot be assumed equivalent to one dedicated long number per tenant. Never infer provisioned or active number counts from schema or a static prefix.
- Distinguish scheduled payload groups from recipient throughput; inspect where chunking occurs and how response references map to repeated recipients. A telephone-based refId is correlation, not a unique idempotency key.
- Verify profile/whitelist behavior for every entry point before running tests. A non-dev client may also be active under QA/testrunner, and raw-number sends may bypass a whitelist used by user-based sends. Do not execute an integration test without a network-isolated or explicitly authorized test path.
- Separate DLR presence from terminal-status correctness, multipart aggregation, replay protection, early-callback handling and actual UI behavior. State frontend limitations for backend-only reviews.
- Treat message rows, recipient rows, API requests, deliveries and billable segments as different volume measures. Optional persistence, retention and scheduled times prevent simple DB counts from proving monthly spend.
- Inspect logging toString overrides and error paths; omitted destination/body can still leak telephone data through refId, and normal masking does not prove malformed payloads are masked.
- Redact credentials and actual phone literals before sharing. Report config/env names only, with provider endpoints stripped of credentials/query data. Upload only the sanitized report, never the source archive or credentials.
- Validate every cited path and line range programmatically, use commit permalinks, and compare a source hash manifest before/after to prove read-only handling. Label tests as inspected rather than passed unless actually executed.
- When target-provider capabilities come from the user rather than inspected docs, label them as premises. Separate high-level feature presence from exact authentication, payload, callback, scheduling, Unicode, sender provisioning and idempotency compatibility.
